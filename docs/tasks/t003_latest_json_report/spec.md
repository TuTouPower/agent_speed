# Task spec

## 背景

契约 §6/§7.2 要求 `latest.json` 由 `results.jsonl` 重新生成：每个格子只看最新 batch、上站规则、中位数、覆盖写。本 task 实现报告脚本。

## 契约区

### 范围

- `report.py`：读 `results.jsonl`（契约 §7.1 schema）→ 生成 `latest.json`。
- 上站规则与中位数计算。
- 单测（构造 `results.jsonl` fixture）。

### 非范围

- 不渲染页面（站点仓库负责）。
- 不重算原始指标（由 t002 写入）。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：每个格子只取最新 `batch_id`；更早 batch 不参与，不补位。
- [ ] AC-002：最新 batch 有效次数 < 2 的格子不上站；原始行保留在 `results.jsonl`。
- [ ] AC-003：输出 token < 500 的调用无效；调用失败且补测后仍失败的不计入。
- [ ] AC-004：对方账单输入 token < 切片 cl100k 一半的格子不上站。
- [ ] AC-005：无生成窗口的格子（codex）照常上站，生成 TPS 为 null。
- [ ] AC-006：`latest.json` 覆盖写，行数等于上站格子数；字段含场景、通道、模型、effort、有效次数、端到端 TPS 中位数、生成 TPS 中位数、TTFT 中位数、输出 token 中位数、对方账单输入 token 中位数、`batch_id`、生成时间；按端到端 TPS 降序。
- [ ] AC-007：各项中位数由有效次数计算，不是全部次数。

### 有意不测

- 页面渲染与部署：不在本仓。
