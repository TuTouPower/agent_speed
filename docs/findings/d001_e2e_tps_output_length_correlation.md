# d001 200K 场景下端到端 TPS 与输出 Token 数量强正相关，纯生成 TPS 才是真实物理指标

- 来源：`s001_e2e_tps_length_dilution_and_decode_tps`
- 结论：200K 长输入场景下，固定的预填耗时（TTFT，约 12~15s）会导致端到端 TPS（输出 token / wall）随输出长度增加而被大幅稀释提升（从 114 飙升到 196），存在严重的长度偏差；真正反映模型物理生成速度的是去除预填时间后的流式生成 TPS（稳定在 255~273 tok/s）。
- 证据：`cpa/gemini-3.8-flash` 在输入均为 27 万 token 下，输出 3,869 token 时端到端 TPS 为 114.77，输出 10,575 token 时端到端 TPS 为 196.54，而两者的生成时间窗 TPS 均恒定在 255~273 tok/s。
- 影响：指导基准评测报告与展示站的指标权重设计；在长上下文评测中不能仅看端到端 TPS，必须重点呈现不含预填的纯生成吞吐。
- 现状：有效
