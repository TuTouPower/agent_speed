# 语料切片与公开评测任务规范 (Corpus & Prompt Spec)

## 1. 概述与目标

为 coding agent 与大模型测速基准提供标准化、公开可复现的 200K 长上下文评测语料及任务 Prompt，确保测速输入的确定性与合规性。

## 2. 语料源与版本锁定

- **上游源码**：采用 `django/django` 官方仓库，强制 pin tag 为 `6.1.1`（对应 commit `249b13d6e93ee3164dee8ed1775395622a50c337`）。
- **内容纳入范围**：
    - 仅纳入 `django/` 下的 Python 源码与 `docs/` 下的官方文档。
- **排除规则**：
    - 严格排除测试目录与文件（`tests/`、`js_tests/`、`tests.py`）。
    - 严格排除数据库迁移目录（`migrations/`）。
    - 严格排除本地化语言包（`locale/`）。
    - 严格排除构建配置、外部工具脚本（`scripts/`、`extras/`）及二进制文件。

## 3. 切片分级与组装规则

- **分词器基准**：统一使用 OpenAI `cl100k_base` 分词器进行 token 计数。
- **分级档位**：
    - `10K`（10,000 tokens）
    - `100K`（100,000 tokens）
    - `200K`（200,000 tokens，MVP 主力场景）
- **路径有序与截断**：
    - 文件按相对路径字典序排序后逐个拼接。
    - 拼接达到各档目标 Token 阈值时停止，允许最后一个文件在边界处被截断。
- **前缀递进约束**：
    - `10K` 切片严格为 `100K` 切片的字节前缀。
    - `100K` 切片严格为 `200K` 切片的字节前缀。
- **清单伴随（Manifest）**：
    - 每个切片均生成同名的 `.manifest.json`，完整记录切片 token 计数、Git commit、纳入文件数及按序排列的文件路径与各自 token 数。

## 4. 评测任务 Prompt 规范

- **文件位置**：`prompts/task_200k.md`（并在 `fixtures/task_200k.md` 同步保留）。
- **语言与形态**：采用中文自然语言编写，作为单一任务描述直接提供给被测模型。
- **任务内容要素**：
    1. 要求模型通读切片内的完整 Django 代码库与文档。
    2. 输出系统的整体架构分层。
    3. 梳理核心模块与组件的职责。
    4. 剖析请求与响应生命周期中的核心数据流。
    5. 总结 Django 的核心设计模式与技术选型考量。
- **安全与环境约束（硬性限制）**：
    - Prompt 明确声明严禁调用任何外部工具、命令或插件。
    - 严禁对本地文件系统执行读写操作。
    - 仅基于提示词内提供的上下文完成纯文本架构分析。

## 5. 许可证与存储规范

- 切片文件与 manifest 均纳入 Git 版本控制（位于 `fixtures/` 目录）。
- 保留原始项目许可证声明：在 `fixtures/LICENSE.django` 随切片附带 Django 的 3-Clause BSD License。
