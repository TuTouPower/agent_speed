# 聚合报告与上站规范 (Latest Report Spec)

## 1. 概述与目标

定义从原始测速调用明细 `data/results.jsonl` 中过滤、清洗、聚合生成公开基准展示数据 `data/latest.json` 的计算规则、上站门槛与输出契约。

## 2. 批次隔离规则

- **最新 Batch 锁定**：
    针对每个网格单元（以 `scenario + model + effort + source + harness` 区分），系统按调用时间严格锁定其最新一次被执行的 `batch_id`。
- **历史 Batch 隔离**：
    仅提取最新 `batch_id` 下的调用记录参与计算。更早批次的测试记录绝不参与当前聚合，也绝不跨批次补位。

## 3. 上站门槛与有效性判定

### 3.1 单次调用有效性

在最新批次中，一条调用记录被判定为「有效」必须同时满足：

1. **执行状态成功**：`status == "success"`（排除 `failed` 与 `skipped`）。
2. **有效输出下限**：输出 token 数 `out_tokens >= 500`（低于 500 视为异常短回复或幻觉崩溃）。

### 3.2 网格单元上站门槛

一个网格单元最终能否被收录进 `data/latest.json`，必须同时通过以下两项硬性门槛：

1. **有效调用次数门槛**：
    最新批次内的有效调用次数必须 `>= 2`。
2. **上下文防作弊 / 账单输入门槛**：
    对方服务商事件流返回的账单输入 token 数（`in_tokens`）的中位数，必须 `>=` 该场景切片 cl100k token 数的一半。
    - 在 200K 场景下，账单输入中位数必须 `>= 100,000` tokens。低于此门槛表明模型未实际接收或截断了上下文，拒绝上站。

## 4. 统计指标与聚合算法

- **中位数计算口径**：
    所有上站指标（端到端 TPS、生成 TPS、TTFT、输出 token、账单输入 token）均使用按时间最近的最多 4 次**有效调用**数据计算中位数（Median），不计入无效或失败调用。
- **生成窗口为空的处理**：
    无生成窗口的运行框架（如 codex）在通过有效门槛后正常上站；其 `gen_tps` 指标输出为 `null`，不影响端到端 TPS 的计算与排名。
- **排序规则**：
    聚合完成的所有上站网格按 **端到端 TPS（`e2e_tps`）降序** 排列。

## 5. 输出格式与契约（`data/latest.json`）

- **文件操作**：全量覆盖写入 `data/latest.json`，全仓唯一榜单输出文件；只收录当前 `config/benchmark.yaml` 矩阵内格子（配置已删模型不上榜，`results.jsonl` 明细保留）。
- **结构契约**：
    - 顶层为扁平数组，行内 `scenario` 自描述，按 200k / 10k / sentence 分档块拼接，各档互不混排。
    - 每个上站网格包含 13 个规定字段：
        - `scenario`: 评测场景（如 `"200k"`）
        - `model`: 模型名称
        - `effort`: 思考强度/变体
        - `source`: 服务商来源
        - `harness`: 运行框架
        - `valid_reps`: 有效调用次数
        - `e2e_tps`: 端到端 TPS 中位数
        - `gen_tps`: 生成 TPS 中位数（允许为 `null`）
        - `ttft`: 首字延迟中位数（秒）
        - `out_tokens`: 输出 token 中位数
        - `in_tokens`: 账单输入 token 中位数
        - `batch_id`: 所属批次 ID
        - `generated_at`: 报告生成时间
